КАЛЬКУЛЯТОР ШИНОМОНТАЖА — ОБЩИЙ ПРАЙС

Внутри — последняя версия калькулятора (v7), PWA-манифест, иконки, офлайн-кэш и интерфейс подключения общего прайса через Supabase.

ВАЖНО: синхронизация не заработает до одноразовой настройки Supabase и публикации на HTTPS-хостинге. В архиве нет ваших облачных ключей/аккаунта, поэтому публичный адрес приложения ещё не создан.

ОДНОРАЗОВАЯ НАСТРОЙКА ОБЩЕГО ПРАЙСА
1) Создай проект в Supabase (https://supabase.com/).
2) В Authentication → Users создай/подтверди пользователя владельца с email, который будет управлять прайсом. Задай пароль.
3) Открой supabase_setup.sql и замени REPLACE_WITH_OWNER_EMAIL на точный email владельца. Выполни весь SQL в SQL Editor.
4) В Supabase Project Settings → API возьми Project URL и публичный anon/publishable key. НЕ используй service_role/secret key в браузере.
5) Опубликуй содержимое архива на HTTPS-хостинге (например GitHub Pages). Файлы должны быть в корне сайта.
6) Открой сайт в Chrome, вкладка «Прайс и настройки» → «Общий прайс — синхронизация». Введи Project URL и anon key, нажми «Подключить общий прайс».
7) Введи email и пароль владельца, нажми «Войти владельцем».
8) Импортируй старый JSON-прайс, если нужно, затем нажми «Опубликовать текущий прайс для всех».
9) На остальных телефонах открой тот же URL, введи Project URL и anon key и нажми «Подключить общий прайс». Остальные смогут читать общий прайс, но не публиковать изменения.
10) В Chrome выбери ⋮ → «Установить приложение» / «Добавить на главный экран». Открой его один раз онлайн; интерфейс будет кэшироваться для офлайн-запуска. Облачная синхронизация требует интернета.

ОБНОВЛЕНИЯ КОДА
Код приложения размещается на хостинге. Для обновления функций заменяй файлы сайта новой версией и повышай CACHE в service-worker.js (например v2), чтобы обновить офлайн-кэш. Пользовательские прайсы хранятся отдельно в Supabase и не стираются при замене файлов приложения.

БЕЗОПАСНОСТЬ
- Никогда не помещай service_role/secret key в HTML.
- Только адрес проекта и anon/publishable key допустимы в клиентском приложении.
- Защита записи задаётся RLS-политиками по email владельца в supabase_setup.sql.
- Перед первым запуском проверь вход владельца и попробуй изменить тестовую цену с другого устройства: у второго пользователя изменение не должно публиковаться.
- Если хочешь передавать приложение другим, делись ссылкой на HTTPS-сайт, а не приватными паролями.
