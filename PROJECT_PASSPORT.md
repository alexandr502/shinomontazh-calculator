# Паспорт проекта — Калькулятор шиномонтажа

**Дата актуализации:** 6 ноября 2026  
**Основная ветка:** `main`  
**Последняя известная версия кэша:** `tirecalc-prod-v53`  
**Состояние:** приложение работает, офлайн-загрузка прайсов восстановлена по результатам пользовательской проверки.

## 1. Назначение проекта

PWA-калькулятор для сотрудников шиномонтажа.

Основные задачи:
- расчёт стоимости шиномонтажных работ;
- использование единого прайса для сотрудников;
- управление ценами владельцем;
- дополнительные услуги и модули покраски;
- формирование итогового расчёта;
- работа без интернета после предварительной загрузки приложения.

Главные приоритеты — стабильность, простота мобильного интерфейса и сохранность данных.

## 2. Адреса и структура проекта

- GitHub: https://github.com/alexandr502/shinomontazh-calculator
- Производственный сайт: https://alexandr502.github.io/shinomontazh-calculator/
- Основная ветка: `main`.
- Главный файл приложения: `index.html`.
- Офлайн-режим: `service-worker.js`.
- PWA-манифест: `manifest.webmanifest`.

Производственной является публикация GitHub Pages из ветки `main`. Vercel используется отдельно для тестирования. Не путать тестовый адрес с производственным.

## 3. Технологии

- HTML, CSS и JavaScript.
- PWA для установки на мобильные устройства.
- Service Worker и Cache Storage для офлайн-работы.
- LocalStorage для локальных данных.
- Supabase для общего прайса и авторизации владельца.

Основной ключ локальных данных: `tireCalcData`.

Общий прайс хранится в таблице `public.shared_price`, запись с `id = 1`.

Доступ к публикации общего прайса ограничивается политиками RLS.

**Безопасность:** не записывать в паспорт пароли, токены, секретные ключи и другие конфиденциальные данные. Никогда не помещать `service_role` или secret key в клиентский HTML.

## 4. Основные функции

В приложении реализованы:
- калькулятор шиномонтажа;
- категории автомобилей;
- прайс по размерным группам дисков;
- дополнительные услуги;

- покраска суппортов;

- адаптивный мобильный интерфейс.

Скрытый вход в настройки владельца открывается пятью нажатиями по строке статуса общего прайса.

Состав категорий, услуг и размерных групп может меняться. Перед доработкой всегда проверять актуальный код.

## 5. Сохранность данных

Это критически важный раздел.

Запрещено без отдельного согласования:
- очищать LocalStorage;
- очищать Cache Storage;
- удалять или перезаписывать `tireCalcData`;
- сбрасывать прайс к исходным значениям;
- удалять Service Worker;
- сбрасывать данные сайта;
- менять настройки Supabase и политики доступа.

При диагностике офлайн-режима ошибки сетевых запросов Supabase ожидаемы. Например, `ERR_CONNECTION_CLOSED` при выключенном интернете не означает, что локальное приложение сломано.

Главное — проверить, завершилась ли локальная инициализация и появились ли цены.

## 6. Версия и обновление кэша

Последняя известная версия:

В `index.html`:
`bootVersion = 'tirecalc-prod-v53'`

В `service-worker.js`:
`CACHE = 'tirecalc-prod-v53'`

Обе версии должны совпадать.

Правила:
1. Сначала выполнить необходимые изменения кода.
2. После этого обновить версию кэша в обоих файлах.
3. Проверить, что значения совпадают.
4. Опубликовать изменения.
5. Проверить работу приложения онлайн и офлайн.

Не повышать версию кэша после каждой отдельной правки, если можно сначала закончить весь согласованный набор изменений.

### Инцидент 6 ноября 2026: отсутствие прайса офлайн

**Симптом:** онлайн приложение показывало цены, а офлайн отображались заголовки и прочерки вместо строк прайса.

**Причина:** первый JavaScript-скрипт обращался к элементам `export`, `importFile` и `defaults`, которых не было в HTML. Присваивание обработчика `.onclick` для `null` вызывало TypeError и прерывало выполнение скрипта.

Онлайн-загрузка общего прайса маскировала проблему.

**Исправление:** обращения к отсутствующим элементам защищены проверкой их существования.

После исправлений кэш обновлён до `v53` в обоих файлах.

GitHub Pages успешно опубликовал изменения. Владелец сообщил, что офлайн-загрузка прайсов и расчёты после обновления «вроде работают».

При следующих доработках обязательно повторять офлайн-проверку.

## 8. Правила работы над проектом

Обязательные правила для всех последующих чатов:

1. Перед правкой всегда получать актуальный файл из GitHub.
2. Не использовать старые номера строк.
3. Давать только одну инструкцию за раз.
4. Указывать точный номер строки и точный фрагмент для замены.
5. После каждого сохранения заново получать актуальный файл.
6. Не менять соседний код без необходимости.
7. Не проводить сбросы данных без согласования.
8. Проверять сохранение изменений непосредственно в GitHub.
9. Проверять совпадение версий кэша в двух файлах.
10. После публикации давать именно адрес сайта, а не ссылку на ветку или репозиторий.
11. Не считать успешную публикацию доказательством того, что приложение на телефоне уже обновилось.
12. Проверять реальную работу на устройстве.

Пользователь предпочитает ручное редактирование через GitHub с точными пошаговыми инструкциями.
